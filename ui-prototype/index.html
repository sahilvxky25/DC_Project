    Mark where frames start and end

    A receiver needs to know where one frame stops. Three common methods, shown with sample data.

    A length field at the start says how many bytes follow. This frame carries “Hello”.

    5bytes in
    6bytes out
    +1overhead

    Flag bytes mark the edges. If the data itself contains a flag or escape byte, an escape is added in front of it.

    Error injection

    Preview only. These controls will flip bits in the sent data.

    Even parity: one extra bit makes the count of 1s even. Sent byte is 01001000, parity bit last.

    Received, 1 bit flipped

    Error detected. The received bits hold three 1s, which is odd.

    Received, 2 bits flipped

    Not detected. Two flips cancel out, so the count of 1s stays even.

    The sender adds the bytes and sends the inverted sum. The receiver’s total should come out as 0xFF.

    Error detected. Data and checksum add up to 0x10, not 0xFF.

    A CRC treats the data as one long number and divides it by a fixed polynomial. The remainder is sent along.

    Received, first byte corrupted

    Error detected. The receiver’s remainder is not zero.
